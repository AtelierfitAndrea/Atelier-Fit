# RCA — virtual-try-on-334 (Atelier Fit)

Live URL: https://virtual-try-on-334.emergent.host
Active run: 411c3e92-d50b-4101-8c71-b20df28c3fd1 (redeploy, success, 2026-10-16T21:41Z)
Frontend type: cloudflare (static assets served from R2 via worker)

## Problem statement
On live, `/?atelier=2026` and `/atelier` reportedly still show the black "MY ATELIER … COMING SOON" gate, and `/admin-atelier-77` (admin dashboard) does not work. In preview the bypass works. Custom domain `myatelierapp.it` fails DNS (ERR_NAME_NOT_RESOLVED).

## Investigation & evidence

### 1) Deployed build is STALE vs current preview — CONFIRMED
- Active run source (`/app/frontend/src/components/ComingSoon.jsx`): `const OWNER_KEY = "atelier_owner"`. Report says current preview uses key `owner`.
- `grep -rn 'admin-atelier' frontend/src` → **NO admin-atelier in src**. App.js in the active run has **no `/admin-atelier-77` route**; the gate runs in `AppRouter` before routing (`if (!isOwner && location.pathname !== "/termini") return <ComingSoon/>`).
- Live-served bundle `https://virtual-try-on-334.emergent.host/static/js/main.e71b23ae.js`:
  - `atelier_owner` → 1 occurrence (matches stale source key)
  - `admin-atelier` → **0 occurrences**
  - bypass logic IS present: `...pathname.startsWith("/atelier")||"2026"===e.get("atelier")...`
- Conclusion: the production build was built from code OLDER than the current preview. The current preview changes (the `/admin-atelier-77` route; localStorage key rename to `owner`) were never deployed. → `/admin-atelier-77` cannot resolve to the admin dashboard in production because that route does not exist in the deployed bundle.
- Note: the `atelier=2026` / `/atelier` owner bypass DOES exist in the live bundle, so on the emergent.host URL that part should already function client-side. If coming-soon still appears there, it is most likely a cached older JS bundle in the browser (hard refresh / incognito).

### 2) SPA deep-path routing — WORKS (not the cause)
- preview_health_check: `/atelier` → 200, `/admin-atelier-77` → 200, `/?atelier=2026` → 200, all serving the real Atelier Fit `index.html` (not nginx default). Query strings are read client-side so preserved. The Cloudflare worker correctly falls back to index.html for deep paths. No routing fix needed.

### 3) Custom domain — BROKEN (DNS not pointed)
- list_domains: `myatelierapp.it` verified=false, `www.myatelierapp.it` verified=false (provider cloudflare).
- check_domain_status: both → "A records do not point to expected IPs" (linked=false). This is exactly the ERR_NAME_NOT_RESOLVED observed. SSL cannot be issued until DNS points to us and the domain verifies.

## Root cause
Two independent real issues:
1. Production is running an OLDER build than the current preview — it lacks the `/admin-atelier-77` route (and uses the old `atelier_owner` localStorage key). A redeploy of the current preview code is required for the admin dashboard to exist in production.
2. Custom domain DNS is not pointed at Emergent (both apex and www unverified; A records don't match), so `myatelierapp.it` does not resolve and SSL is pending.

The `atelier=2026`/`/atelier` bypass itself is already in the live bundle; the SPA routing is correct. Any residual coming-soon on the emergent.host URL is a stale cached bundle, not a server/build gap for the bypass.

## Fixes
1. Redeploy the current preview build so production picks up the `/admin-atelier-77` route and the latest ComingSoon logic. (The code is already correct in preview; this is a deploy, not a code change.)
2. User: in Deployment Panel → Domains, set the DNS A records for `myatelierapp.it` and `www.myatelierapp.it` exactly as shown, then wait for verification + SSL issuance. Use https://virtual-try-on-334.emergent.host meanwhile.
3. User: test the bypass on the emergent.host URL in a fresh/incognito session (hard refresh) to clear the cached older bundle; confirm `/?atelier=2026` and `/atelier` render the app. `/admin-atelier-77` will only work after fix #1.
