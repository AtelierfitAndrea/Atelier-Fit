# RCA — myatelierapp.it Stripe webhook (pending_webhooks=1)

## Problem statement
Live event `evt_1UULZwC7OX8nXTMUZJ8iXvrl` (checkout.session.expired) left `pending_webhooks=1`; delivery to `POST /api/stripe/webhook` failing. Two questions: (1) was STRIPE_WEBHOOK_SECRET updated in the last hour and has a redeploy happened since; (2) recent webhook status codes + presence of the newest-code marker log `stripe webhook: signature verification failed`.

- Active/serving run: `994fb808-2001-4371-879d-9e40feaae833` (redeploy, success), completed **2026-10-24T23:44:01Z**.
- Current time (eph-pod spawn): **~2026-10-25T07:00Z**. => The latest redeploy was ~7 hours ago. No redeploy in the last hour. Entire recent-run history is on 2026-10-24 (latest 23:44).

## Q1 — STRIPE_WEBHOOK_SECRET updated_at + redeploy since?
- `list_secrets` (active run): `STRIPE_WEBHOOK_SECRET` is **present and non-empty**. (Value never revealed.)
- No tool exposes the secret's `updated_at` timestamp, so I **cannot confirm** whether the value itself was changed in the last hour. (UNVERIFIED by design.)
- **A redeploy has NOT happened in the last hour** (last redeploy completed 2026-10-24T23:44Z, ~7h ago). Production secrets are only (re)written into the running pod during a deploy run's write_secrets step — so any Secrets-tab edit made in the last hour is **not live** in the current pod.

## Q2 — webhook status codes + marker line (last 10 min)
- Logs: 2× `POST /api/stripe/webhook HTTP/1.1" 400 Bad Request` (from Cloudflare/Stripe source IPs 162.159.114.103, 104.23.243.26). Matches Stripe's failed delivery.
- Marker line `stripe webhook: signature verification failed`: **ABSENT** (searched run logs over 10–20 min, 0 matches).
- Definitive source check (eph pod on the active run's deployed source): the string does **not exist anywhere** in the deployed backend. `grep -rni 'signature verification failed' backend` → MARKER_NOT_FOUND. The deployed handler (`backend/server.py:1047`) raises `HTTPException(400, "Invalid signature")` on failure and logs nothing.

## Root cause
1. The deployed image (active run) is the **OLD code** — the newest code that emits the `stripe webhook: signature verification failed` marker is **not live**; no redeploy has happened since it was written. This is why the marker never appears.
2. The webhook returns **HTTP 400 "Invalid signature"** — the running pod's `STRIPE_WEBHOOK_SECRET` does not verify Stripe's signature for this endpoint. Either the secret baked into the current run is stale/wrong for this endpoint, or an updated value sits in the Secrets tab but hasn't been shipped (no redeploy). This is what leaves `pending_webhooks=1`.

## Fix
- **Redeploy** to ship the newest code AND apply any Secrets-tab change (both only take effect on a new run).
- **Verify STRIPE_WEBHOOK_SECRET** equals the signing secret (`whsec_...`) of *this exact* webhook endpoint in the Stripe Dashboard, since the live pod returns 400 Invalid signature. Correct it in Deployment Panel → Secrets, then redeploy.

Did NOT deploy or change any secret.
