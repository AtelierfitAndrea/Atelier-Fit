# RCA — Stripe webhook 400 "Invalid signature" on production (myatelierapp.it)

## Problem statement
Stripe webhook `POST https://myatelierapp.it/api/stripe/webhook` has been failing since Oct 22 (13 failed deliveries). Reporter reproduced: a payload signed with the PREVIEW `STRIPE_WEBHOOK_SECRET` returns 200 on preview but 400 "Invalid signature" on production — implying the production `STRIPE_WEBHOOK_SECRET` differs from preview.

## Scope / environment
- Deployment: `virtual-try-on-334` (deployment_id 816103ce-e2c8-443a-991b-6321c94201e4)
- Active run: `994fb808-2001-4371-879d-9e40feaae833` (redeploy, success) — serving traffic
- Frontend: cloudflare; template: fastapi_react_mongo_shadcn_base_image

## Evidence

### 1. Production secret `STRIPE_WEBHOOK_SECRET` exists, is non-empty, and does NOT match preview
`list_secrets` with an expected-value comparison against the current preview `/app/backend/.env` value returned:
```
{"name":"STRIPE_WEBHOOK_SECRET","is_empty":false,"matches_expected":false}
```
- Exists in production: YES
- Empty: NO
- Matches current preview value: NO  ← root cause
(Comparison done server-side; the secret value was never revealed.)

### 2. Preview value is present and non-empty
Read from the run's pulled source `/app/scratch/backend/.env` in an isolated sandbox — `STRIPE_WEBHOOK_SECRET` is set to a valid `whsec_...` value. So preview has a real secret; production simply holds a different one.

### 3. Production backend logs confirm the rejections
`fetch_app_logs` (run 994fb808, last 1440 min, filter `stripe webhook|Invalid signature|stripe/webhook|500`):
```
INFO: 104.22.24.209:0  - "POST /api/stripe/webhook HTTP/1.1" 400 Bad Request
INFO: 104.22.118.80:0  - "POST /api/stripe/webhook HTTP/1.1" 400 Bad Request
```
- POST /api/stripe/webhook → **400 Bad Request** (matches the "Invalid signature" rejection). The source IPs (104.22.x.x) are Cloudflare/Stripe edge, consistent with real Stripe webhook deliveries.
- **No 500 errors** on that route — the endpoint is up and correctly rejecting mismatched signatures, not crashing.
- (The many `GET /health 404` lines are internal probe noise, unrelated to this issue.)

## Root cause
Production `STRIPE_WEBHOOK_SECRET` does not match the signing secret Stripe is using for the live webhook endpoint (and differs from the current preview `.env` value). Stripe signs each delivery with the endpoint's signing secret; the backend recomputes the signature with its configured secret, they don't match, and it returns 400 "Invalid signature".

Why it drifted: per the platform secrets model, on every redeploy a custom key like `STRIPE_WEBHOOK_SECRET` is carried forward from the previous PRODUCTION run (the Secrets-tab value wins); the preview `.env` only ADDS new keys, it never overwrites a key already set in production. So updating preview `.env` alone does not change production — the production value must be set explicitly in the Deployment Panel → Secrets tab.

## Fix (not applied — read-only debug)
**User action:** In Deployment Panel → Secrets, set `STRIPE_WEBHOOK_SECRET` to the signing secret of the LIVE production Stripe webhook endpoint (Stripe Dashboard → Developers → Webhooks → your production endpoint → "Signing secret", `whsec_...`). Then redeploy so the new value is written to the production pod. After redeploy, use Stripe's "Resend"/test to confirm a 200.

Note: confirm the intended value against the LIVE Stripe endpoint's signing secret — the preview `.env` value is for the preview endpoint and may not be the correct production one either. The correct source of truth is the Stripe Dashboard webhook endpoint that points at `https://myatelierapp.it/api/stripe/webhook`.
