# RCA — Stripe LIVE-key verification for myatelierapp.it (deployment virtual-try-on-334)

## Request
User wants all payments on Stripe LIVE keys only. Asked (names / yes-no only, no values):
1. Do production STRIPE_SECRET_KEY and STRIPE_PUBLISHABLE_KEY match the current preview /app/backend/.env values (preview = rk_live_/pk_live_)?
2. Is production STRIPE_SECRET_KEY a live key (sk_live_/rk_live_) or test (sk_test_/rk_test_)? Same for STRIPE_PUBLISHABLE_KEY (pk_live_ vs pk_test_).
3. Is production STRIPE_MODE = 'live'?

Scope: diagnose only; no deploy, no secret change.

## Method / Evidence
- Active (serving) run: 994fb808-2001-4371-879d-9e40feaae833 (redeploy, success). Frontend = cloudflare.
- Preview source read from the run's pulled source in an eph sandbox: `/app/backend/.env` contains:
  - STRIPE_SECRET_KEY = rk_live_… (live)
  - STRIPE_PUBLISHABLE_KEY = pk_live_… (live)
  - STRIPE_MODE = "live"
- Compared production secrets to those exact preview values via `list_secrets` (equals map; values never exposed):
  - STRIPE_SECRET_KEY → matches_expected = FALSE
  - STRIPE_PUBLISHABLE_KEY → matches_expected = FALSE
  - STRIPE_MODE vs "live" → FALSE; STRIPE_MODE vs "test" → TRUE
- Code: `backend/server.py:37` → `stripe.api_key = os.environ['STRIPE_SECRET_KEY']` (key used directly; STRIPE_MODE does not select the key).
- Publishable key is NOT exposed by any backend route or frontend bundle (grep empty). `stripe_sessions` collection only holds `mock_cs_...` demo/test rows — no real Stripe session IDs to read a live/test prefix from.

## Findings
1. NO — production STRIPE_SECRET_KEY and STRIPE_PUBLISHABLE_KEY do NOT match the current preview .env (live) values.
2. UNVERIFIED (prefix) — secret values are never returned by tooling and the app exposes neither key, so the exact prefix of the production keys cannot be read directly. Circumstantial evidence (STRIPE_MODE=test; prod keys differ from the live preview keys) indicates production is NOT on the current live keys, but the literal prefix is not provable with available tools.
3. NO — production STRIPE_MODE = "test" (not "live").

## Root cause
On redeploy, pre-existing custom secrets in production are carried forward from the previous production run and are NOT overwritten by the preview .env (preview .env only ADDS new keys). The user updated the preview .env to live keys, but production still holds older/different STRIPE_SECRET_KEY / STRIPE_PUBLISHABLE_KEY values and STRIPE_MODE=test. This is the classic "live in preview, stale in prod" case — a redeploy alone will NOT push the preview live keys into production.

## Fix (not applied — user requested no changes)
User action in Deployment Panel → Secrets: set STRIPE_SECRET_KEY = rk_live_… and STRIPE_PUBLISHABLE_KEY = pk_live_… to match the intended live values, set STRIPE_MODE = live (and review STRIPE_WEBHOOK_SECRET so it is the live-mode webhook signing secret), then redeploy. Verify after redeploy that all three match preview.
